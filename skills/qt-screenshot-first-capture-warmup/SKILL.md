# Qt 截图首次触发预热

## 什么时候用

- PySide6/PyQt 截图工具启动后，第一次按全局快捷键或双击托盘图标需要 1–5 秒才显示截图遮罩。
- 后续截图明显更快，说明延迟来自首次抓屏、首次创建置顶全屏窗口或首次 Qt 图形资源初始化。

## 关键步骤

1. 给截图关键路径加耗时日志，分别测量用户触发到回调执行、首次抓屏、遮罩创建、show/raise 和首帧绘制。
2. 在事件循环启动后用 QTimer.singleShot(0, warmup) 调度预热，不要在 app.exec() 前同步执行。
3. 预热时执行一次桌面抓取，并为每块显示器提前创建独立遮罩窗口。
4. 遮罩用完全透明、鼠标穿透方式短暂 show() 和 raise_()，随后定时隐藏；不得污染截图或抢占用户输入。
5. 后台线程只处理 QImage 解码，QPixmap 和窗口对象仍在 GUI 主线程创建。
6. 单文件版和模块版存在并行入口时必须同步修改。

## 踩坑

- 仅实现 _warmup() 但未从启动调度调用，实际不会产生任何加速。
- 把历史会话恢复放在启动关键路径会阻塞托盘与全局热键；历史截图应惰性恢复。
- 托盘原生消息回调中直接显示全屏窗口可能受 Windows 前台激活锁影响，可延后一拍，但延迟应控制在几十毫秒。
- 全透明窗口在部分 Windows 合成路径中可能无法完成真正预热；需要用耗时日志和实机首帧表现验证。

## 验证

- 执行 validate_python(path=".")。
- 执行项目现有标准 unittest；若全量测试会导入 Qt 事件循环脚本而超时，运行覆盖截图/会话逻辑的稳定测试文件并明确记录限制。
- 冷启动后立即测试全局快捷键和托盘双击，比较日志中首次与第二次截图的触发到遮罩显示耗时。
